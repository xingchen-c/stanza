# 歌词候选匹配、手选与缓存

> 最近核对：2026-11-20。统一决策已实现；实网准确率与等待时间仍需验收。源码主要位于 `Stanza/Services/Lyrics/`，人工列表过滤位于 `Stanza/LyricsPickerWindow.xaml.cs`。

## 1. 当前范围

```text
可信 LyricsQuery → 优先读取手选记忆及候选缓存
                → 自动决策缓存
                → 多源搜索候选 → 统一排序及置信判断
                → 按候选串行取词 → 同平台偏好及歌词质量选择 → 决策缓存
```

- QQ、网易云、LRCLIB 只提供搜索元数据和按 ID 取词；自动与手动共用 `LyricsCandidateRanker`。
- 只并行搜索；收集完预算内的结果再统一判断，禁止并行多个 `LoadAsync` 抢答。
- 匹配等级说明元数据的相似程度，不是选对概率，也不代表候选一定有可用歌词。

## 2. 时长归属与播放来源

`LyricsQuery` 包含标题、完整歌手、可空时长、专辑和可空 `PreferredSourceKey`。

`TrackDurationEvidence` 在会话切换时重置：首次接入可接受有效时间线，保留歌曲播放中段启动的行为；后续曲目 key 变化，只接受时间戳不早于本次元数据确认的快照。时间戳退化、时长无效或属于上一首时均传空。此约束仅影响歌词匹配，不改变位置外推或播放器阈值。

播放层将已知平台映射成来源提示：QQ → `QQ`、网易云 → `NetEase`；实机 `Tencent.QQMusic` 即使落入 Generic 播放策略，也保留 QQ 歌词偏好。未知播放器中立。提供器不依赖播放策略。

## 3. 统一排序与置信度

每个候选按来源和 ID 去重后，以完整查询重新调用 Lyricify.Lyrics.Helper 0.2.0 的 `CompareHelper.CompareTrack`。不信任提供器已经计算的分数，不再叠加原五维权重。

```text
核心歌名一致 → 版本标记一致 → 歌手档 → Lyricify 匹配等级
```

- 歌手集合一致、包含、部分交集等历史识别保留；达到 `0.6` 标为歌手匹配。没有匹配歌手时仍保留同名候选供人工纠错，自动流程返回歧义。
- 等级归一值为 Perfect `1.00`、VeryHigh `0.99`、High `0.95`、PrettyHigh `0.90`、Medium `0.70`、Low `0.30`、VeryLow `0.10`、NoMatch `0`。
- 初始自动门槛为 High；Perfect / VeryHigh 为同一置信档，High 为另一档。门槛来自库的现有等级，后续依据真实样本校准。
- 没有核心同名且版本一致的候选时为 `NotFound`；低于自动门槛、缺少匹配歌手，或最高置信档仍有不同录音时为 `Ambiguous`。
- 歧义不缓存；界面提示选择歌词版本。恢复流程可等待新元数据再判断，持续不可读时保留已有歧义，不改称“未找到”。

同录音证据采用保守近似：相同来源及 ID；或版本标记一致、歌手完全匹配，且双方时长相差不超过 2 秒。缺失时长时，需有相同非空专辑。该规则不能证明音频或时间轴完全一致，未识别的重录与版本标记仍需人工纠错。

## 4. 同平台偏好与歌词质量

来源偏好不增加匹配分。只有核心歌名、版本、歌手档、置信档及同录音证据一致的小组，才优先当前播放器对应的歌词源。

- 同源 Live、伴奏或明显不匹配的版本不能因来源偏好获准自动采用。
- 其他来源证据明显更好时优先采用其他来源。
- 按已通过决策的候选依次取词；同源候选失败继续尝试其他来源，受总预算约束。
- 同录音结果先比较置信档，再比较同平台偏好，最后比较逐字、翻译质量；最终相同才沿用注册/搜索顺序。
- 纯音乐先保留为兜底，仍继续寻找可用同步歌词。

## 5. 搜索召回与人工列表

搜索可清洗标题以扩大召回，判定同曲使用严格核心歌名 `IsSameSongTitle`，不再允许任意包含关系自动准入。

- 可清理前置方括号及白名单版本后缀：Live、Remix、伴奏、现场版、剧情版等。
- “朗诵”“古诗诵读”“儿童古诗词”及作者副标题不能随意忽略；单字“星”也不能匹配“星炬不熄”。
- 版本标记另行比较，识别 Live / 现场、Remix / 混音、伴奏 / Instrumental、剧情版、Remaster 等；去掉后缀获得核心同名，不代表版本也相同。
- 手动列表始终过滤异歌；默认有匹配歌手时隐藏明确不匹配项，勾选只放宽其他歌手的同名版本。
- 没有匹配歌手时保留同名结果；同名不同版本可手选，并显示版本差异和“与当前播放器同源”标记。
- 界面显示“匹配等级分”，避免把等级值误读为选对概率。

## 6. 用户选择与决策缓存

成功手选先取消恢复并开启新 generation，直接按来源及 ID 取词；Loaded 后记忆候选，写候选专用缓存及兼容普通 key。后续优先查候选专用缓存，可离线复用；旧普通缓存不能冒充所选候选。记忆候选失败后可回到自动流程。

```text
选择记忆 key：TrackKey.Of(title, artist)
候选缓存 key：candidate:{曲目key长度}:{曲目key}{来源长度}:{来源}{候选ID}
自动缓存 key：auto:{算法版本}:{查询指纹}
```

自动查询指纹为包含标题、歌手、时长、专辑、来源偏好的查询 JSON 的 SHA256；当前算法版本为 `2`。缓存结果另带算法版本、查询指纹和完整候选信息，保留来源及候选 ID。内存和 SQLite 都保存该证据；SQLite 兼容旧数组 payload，已有手选缓存仍可用，旧普通自动结果不会命中新 key。

手选失败或取消时保留已有歌词；当前无歌词且查询仍属于同曲时，以当前 generation 恢复加载。切歌或后发手选接管后，不恢复旧请求。纯音乐可临时应用，但不写本次手选记忆和候选缓存。

## 7. 跨请求一致性

- `LyricsSelectionContext` 固定曲目 revision；搜索、返回和应用均校验上下文，A → B → A 后原窗口也失效。
- generation 控制在飞请求；同曲自动晚到不得覆盖手选显示、状态或缓存。
- 正常切歌后，旧自动请求只可缓存自己的查询结果，不能发布到新歌。
- 每次 await 后同时保护歌词行、状态、恢复、选择记忆及缓存副作用。
- 取消停止等待与发布；由于提供器接口不接受 token，底层网络操作可能继续，迟到异常会被观察。

## 8. 超时与恢复

- 默认单源预算 5 秒、自动链总预算 8 秒。搜索并发，全部搜索最多等待单源与总预算的较小值；失败源不丢弃其他源已返回的候选。
- 自动取词串行，共享搜索后剩余总预算；每次等待不超过 5 秒。
- 手选候选取词默认最多等待 5 秒，支持取消。
- NotFound / Ambiguous 均可进入现有有界恢复；元数据稳定后重新决策，取消或切歌后不发布旧结果。
- 选择窗口立即显示加载态，支持取消、重搜；列表在聚合完成或预算结束后返回。

主要入口：`LyricsDecisionTests`、`TrackDurationEvidenceTests`、`LyricsRecoveryTests`、`LyricsProviderChainTests`、`LyricsGenerationTests`、`LyricsSelectionTests`、`SqliteStorageTests`，以及保留的 QQ 搜索/解析、严格同名和人工列表测试。

已锁定：七夕旧时长隔离、唤归双歌手同平台优先、Live/伴奏/Remix 冲突、豆蔻歌手与时长冲突、缺失证据、跨源失败回退、歌词质量、手选优先、缓存兼容及取消时序。旧权重公式的专属用例随旧实现删除；业务不变量继续保留。

2026-11-20 离线对照使用历史元数据与合成候选，直接调用旧版生产排序、Lyricify 原生比较与当前决策器；所有候选在此对照中假定可取词，并模拟旧 QQ 优先串行流程。它不代表完整实网候选快照：

| 七夕，仍带旧 286 秒时长 | 244 秒版 | 244 秒版 | 旧时长置空，保留歧义 |
