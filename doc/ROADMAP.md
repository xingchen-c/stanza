# Stanza 演进路线图

> 最近同步：2026-11-13。本文记录方向、未完成项和不做清单；现行架构见 [HANDOVER.md](./HANDOVER.md)，验证结果见 [文档索引](./README.md#最近验证基线)。里程碑版本是规划，不代表当前应用已升级版本。

## 1. 产品方向

**做 Windows 任务栏上“歌词优先的音乐中心”小组件。** 差异化重点是逐字卡拉 OK、翻译、匹配准确率和切歌手感，而不是堆功能。

- **A / compact**：轻量、透明、点击穿透的歌词叠加卡片。
- **B / rich**：封面、播放控制、进度条与歌词常驻的任务栏音乐中心。
- A 与 B 共享同一个内核，不是先做一套、再推倒重来。
- 气质保持透明、轻量、克制；不做亚克力和重动效。

## 2. 架构方向

```text
上游：播放器会话 / 来源策略 / 元数据规范化 / 切歌 FSM
                    ↓ 统一播放上下文
中游：歌词搜索 / 候选排序 / 选择决策 / 取词 / 缓存
                    ↓ 歌词与显示状态
下游：compact / rich 外壳，共享逐字、翻译与跟随滚动
平台：任务栏定位 / 窗口交互 / 全屏 / DPI / 多屏
```

播放器与歌词源是两个正交扩展点。支持一个播放器，不要求使用它自己的歌词源；扩展一个歌词源，也不应改播放器策略。

关键决策：

- **原地演进，不重写、不另起仓库。** SMTC、任务栏、穿透和封面容错都含实际踩坑经验。
- 可在收益明确时小步提取无 WPF 依赖的 `Stanza.Core`，但当前只有主项目和测试项目。目标分层不是一次性大重构的授权。
- 词源继续采用 `ILyricsProvider` 编译期注册；开关、优先级和超时配置化是计划，不是现状。
- 名称已定 Stanza，旧 FluentLyrics 数据迁移继续保留。

## 3. 已完成的阶段基础

这些成果不再列为下一轮施工任务：

- `NowPlaying`、QQ / 网易云 / Generic 来源策略、会话选择器和播放能力投影。
- `PlaybackPositionTracker`、显式 `TrackSwitchStateMachine`、封面管线与适配器。
- `LyricsQuery`、歌词链、内存缓存、协调器、实例化 SQLite repository 和 `AppServices`。
- `NativeMethods`、全屏检测、窗口互操作、任务栏枚举/布局及设置 ViewModel 的阶段性拆分。
- 软件渲染自动降级、日志级别和测试安全网。
- 卡片悬停“换歌词版本”入口、选择器加载/取消/重搜、固定曲目上下文与手选优先保护。
- VeryHigh 评分修正、候选专用离线缓存、手动列表异歌过滤、只展开其他歌手同名版本及选择窗口置顶。

实现完成不等于所有实机组合通过。切歌、跨进程穿透、多屏和休眠恢复仍需按修改范围验收。

## 4. 当前优先级

### P0：稳定 QQ 主流程

- 用真实 QQ 场景持续验收切歌、暂停恢复、快速连切、首次接入中段、外部拖动与迟到封面。
- 验收悬停按钮首击、能力禁用状态、选择窗口置顶、重搜和切歌失效提示。
- 匹配与交互问题优先建立真实业务回归用例，不通过改断言掩盖回归。
- 对网络无词、解析失败、纯音乐和元数据匹配高但取词失败保留可区分的诊断信息。

### P1：统一歌词候选决策

这是自动匹配的最高优先级结构性缺口，详见 [MATCH-SCORING.md 第 11 节](./MATCH-SCORING.md#11-未完成同名多版本与跨源统一决策)：

1. 明确时间线快照归属，不把上一首时长传给新歌排序。
2. 提供器拆出搜索候选与按候选取词，自动和手动共用排序证据。
3. 引入自动 / 手动 / 歧义决策，缓存携带来源、候选 ID、曲目指纹与算法版本。
4. 保留手选优先和没有匹配歌手时的降级通道。

当前 `LyricsQuery`、候选专用缓存和手动聚合只是阶段基础；不能把它们等同于完整 `SelectionDecision`。**禁止用多个 `LoadAsync` 并行抢答替代此项。**

### P2：有边界地完善配置与职责

- 播放来源设置 UI：自动 / QQ / 网易云；目前内部有选择模式，设置界面尚未接入。
- 词源开关、顺序和超时配置；目前源顺序固定、预算为常量。
- 继续评估 `MainWindow` 的定位、交互、渲染协调拆分与 `SmtcSessionService` 的职责边界，每次只处理有实际收益的一块。
- 评估可独立测试的 Core 提取，不为了目录整齐复制新旧两套流程。

### 暂缓：网易云播放器新增适配

现有 `cloudmusic.exe` 策略保留。历史实机观察是 Position 恒 0、LastUpdatedTime 退化且不发时间线事件；完整暂停恢复、切歌、拖动、封面与控制矩阵未验收。

当前不猜测专用阈值、不扩充适配，先稳定 QQ；这与网易云**歌词源**是否继续参与回退无关。恢复该方向时先补实机数据，再决定代码修改。

## 5. 里程碑与剩余范围

| 里程碑 | 暂定版本 | 当前阶段 | 剩余重点 |
| --- | --- | --- | --- |
| M0 稳固地基 | 0.2.x | 基础已完成 | 随改动持续回归，不重新执行历史搬迁清单 |
| M1 内核夯实 | 0.3.0 | 进行中 | 匹配统一决策、QQ 实机稳定性、诊断 |
| M2 架构分层 | 0.4.0 | 已完成阶段性拆分 | 配置化、协调器继续减负、按收益评估 Core |
| M3 生态扩展 | 0.5.0 | 部分基础已具备 | 本地 LRC、脏元数据与多会话；更多播放器待实机证据 |
| M4 音乐中心 | 1.0.0 | 未完成 | rich 常驻、主动 seek、任务栏空间管理 |

当前支持外部播放器拖动后的进度同步，**不等于 Stanza 已支持主动 seek**；策略能力仍为 `SupportsSeek = false`。

长期可评估：结构化候选/决策快照、命中率与耗时观测、更多词源、品牌素材。先有问题或证据，再引入相应工程成本。

## 6. 不做清单

- 不引入 DI 框架、运行期 DLL 插件或一次性大规模分层重构。
- 不做亚克力和复杂动效，保持小工具的克制感。
- 不在内核和状态机尚不稳定时，提前堆 rich 形态重型交互。
- 不为无体感且未观测到的性能项单开优化轮次。
- 不继续深挖对 FluentFlyout 的紧耦合；独立定位是战略主路径，锚点模式作为兼容旁路保留。
- 不把路线图当作自动实施授权；每轮任务按用户确认的范围执行。
