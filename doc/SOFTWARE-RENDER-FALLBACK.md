# 软件渲染降级

> 最近核对：2026-11-13。以下行为已实现；描述实现与人工验收，不是待执行的新功能清单。唯一目标平台仍为 Windows 11，早期 Win10 反馈不代表承诺支持 Windows 10。

## 1. 背景与边界

WPF 在缺失显卡驱动、Microsoft 基本显示适配器或部分远程桌面环境中可能使用软件渲染。透明分层窗口的重绘成本会增大；早期还遇到模糊阴影、文字发虚和闪烁。

当前使用偏移文本伪阴影，不再使用 `DropShadowEffect`。降级只调整抗锯齿、卡片底和 ticker 频率，不移除透明窗口，也不改变播放/歌词业务规则。安装正确的显卡驱动仍是恢复硬件加速的首选措施。

## 2. 检测与设置

实现主要在 `Stanza/MainWindow.xaml.cs` 的 `ApplyRenderMode`：

- 软件渲染判定：`(RenderCapability.Tier >> 16) == 0`。
- `CompatibilityMode` 三种设置：`Auto` / `ForceOn` / `ForceOff`。
- Auto 根据 Tier 判断；ForceOn 强制降级，ForceOff 强制使用正常模式。
- 窗口句柄就绪后应用一次；监听 `RenderCapability.TierChanged` 重新应用，关闭时退订静态事件。
- 设置应用时即时调用，不需重启。

## 3. 当前三项降级

| 项目 | 正常模式 | 降级模式 |
| --- | --- | --- |
| 文字抗锯齿 | ClearType | Grayscale |
| `LyricHost.Background` | 透明 | 半透明深色卡片底 |
| ticker 间隔 | 100ms | 250ms |

偏移伪阴影是所有模式共用的视觉方案，**不是降级时关闭的第四项**。降级牺牲部分透明感和逐字刷新流畅度，不应描述成移除阴影。

ticker 同时驱动歌词渲染和窗口交互采样；无会话时仍需维护交互，不能为了省刷新而停止所有采样，导致媒体按钮区域无法恢复可点击状态。

## 4. 不改的窗口机制

- 保留 `AllowsTransparency`、透明分层窗口及原有任务栏定位。
- 点击穿透由 `WindowInterop` 按光标区域动态切换 `WS_EX_TRANSPARENT`，并保留不抢焦点样式。
- 不再把 `WM_NCHITTEST / HTTRANSPARENT` 当作跨进程点击穿透方案。
- 如需进一步改变透明窗口形态，应另行评估交互与定位风险，不作为降级方案的顺手修改。

## 5. 日志与人工验收

`AppLog` 输出渲染 Tier、降级判定与 CompatibilityMode，状态切换记录 Info，重复应用记录 Debug。

| 场景 | 应检查的行为 |
| --- | --- |
| 有硬件加速 + Auto | 透明底、ClearType、100ms；正常视觉不变 |
| 任意机器 + ForceOn | 深色半透明底、Grayscale、250ms，即时生效 |
| ForceOff | 返回正常模式，保存设置后保持选择 |
| Tier 变化 / 远程桌面切换 | 重新判断与切换，无重复订阅或异常 |
| 无会话 / 暂停 / 媒体区悬停 | 穿透状态与按钮交互仍能恢复 |
| 真实低性能环境 | 观察可读性、闪烁、CPU 和长期表现，不能只看 Tier 判定 |

最近编译与自动回归见 [文档索引](./README.md#最近验证基线)。自动测试不等同于实际软件渲染、远程桌面和多 DPI 环境验收；未取得相应设备证据时，不宣称全部兼容问题已经解决。

## 6. 权衡

透明窗口在软件渲染下仍有成本；当前方案通过降低刷新频率与改善对比度缓解，不保证所有驱动环境都不闪烁。若仍有实机问题，先记录 Tier、模式与截图，再决定是否需要进一步降频或视觉调整，不预先添加复杂兼容分支。
